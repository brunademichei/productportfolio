Lumo — iOS Shopping App

A concept iOS e-commerce app designed end-to-end: navigation flows, information architecture, a token-based design system, and three key screens built on Apple's Human Interface Guidelines.

My role
Product Designer (UX/UI)
Platform
iOS (iPhone) — native
Scope
Flows, IA, design system, UI
Focus
Usability, accessibility, HIG

Overview

Lumo is a self-initiated concept for a mobile shopping experience: a curated marketplace where people can discover products, explore details, and check out in a few confident taps. I used it to demonstrate how I design a mobile product end to end — from navigation flows and information architecture to a reusable design system and polished, accessible UI that follows Apple's Human Interface Guidelines.

The goal was a fast, trustworthy purchase journey with strong visual hierarchy, clear affordances, and just enough delight, while keeping every component consistent through design tokens and an atomic component structure.

Goals & principles

  • Usability first: reduce the number of decisions per screen and make the primary action obvious.
  • Accessibility: AA contrast, large tap targets (≥44pt), Dynamic Type–friendly hierarchy, and clear focus/selected states.
  • Platform-native: tab bar navigation, safe areas, large titles, and system gestures per iOS HIG.
  • Consistency: a token-based design system so color, type, spacing, and components stay coherent and scalable.

Navigation flow & IA

The core purchase path is intentionally short. Each screen has a single primary job and a clear next step, so the user always knows where they are and what to do next.

Design system & tokens

Every screen is built from the same foundations. I structured the UI with an atomic approach — tokens feed components, components build screens — so the product stays consistent and easy to hand off to engineering.

Color tokens

Accent, neutrals, and surfaces with AA-compliant pairings for light and dark.

Type scale

Aa

A modular scale for titles, body, and captions, tuned for Dynamic Type.

Spacing & radius

4-pt spacing grid and consistent corner radii across cards, chips, and buttons.

Components

Buttons, chips, product cards, list rows, steppers, tab bar — reusable and state-aware.

Atomic design in practice

I build the UI atomically: design tokens are the atoms, they combine into molecules, molecules into organisms, and organisms compose each screen. This keeps the system coherent, scalable, and easy to hand off.

Handoff & validation

To make the work build-ready, I document use cases and states for each component, annotate spacing and behavior, and specify the primary flows so developers can implement without guesswork. I present decisions to stakeholders framed by the underlying rationale, keeping the message clear and the direction defensible.

The next step for a concept like this is validation: quick usability tests on the purchase flow to confirm hypotheses, plus lightweight analytics (funnel drop-off, tap heatmaps) to guide iteration.
